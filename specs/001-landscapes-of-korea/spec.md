## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스크롤을 따라 네 장소의 풍경과 글을 읽는다 (Priority: P1)

한국 여행에 관심이 있는 국내외 방문자가 페이지에 들어와 Hero의 리드문을 읽고, 아래로 스크롤하며 설악산 → 제주 → 순천만 → 보성 녹차밭 순서로 각 장소의 대표 사진과 두 문단의 소개 글, 풍경 키워드를 차례로 만난다.

**Why this priority**: 이 페이지의 핵심 목적은 사진 감상과 글 읽기를 균형 있게 제공하는 편집형 경험이다. 이 여정이 없으면 사이트의 존재 이유가 없다.

**Independent Test**: 페이지 최상단에서 최하단까지 스크롤하는 것만으로 완전히 테스트 가능하다. 각 장소 섹션에서 사진, 한 줄 제목, 본문 2문단, 키워드가 모두 노출되고 다음 장소로 넘어가기 전 충분히 읽을 시간이 유지되는지 확인하면 이 사용자 여정이 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 방문자가 페이지 최상단(Hero)에 있다, **When** 아래로 스크롤한다, **Then** 제목("한국의 결"), 영문 표기("LANDSCAPES OF KOREA"), 리드문이 먼저 보이고 이어서 설악산 섹션으로 자연스럽게 전환된다.
2. **Given** 방문자가 한 장소 섹션(예: 제주)을 보고 있다, **When** 스크롤을 계속한다, **Then** 다음 장소(순천만)의 이미지가 서서히 확대되며 들어오고, 이전 이미지와 짧게 겹친 후 교차되며, 장소 이름·한 줄 제목·본문이 시차를 두고 등장한다.
3. **Given** 방문자가 한 장소의 본문을 읽기 시작했다, **When** 스크롤을 잠시 멈추거나 천천히 진행한다, **Then** 본문이 등장 즉시 사라지지 않고 읽을 수 있는 시간 동안 화면에 유지된다.
4. **Given** 방문자가 마지막 장소(보성 녹차밭)를 지났다, **When** 계속 스크롤한다, **Then** 마지막 CTA("오래 보고 싶은 풍경은 천천히 남습니다")와 "처음 풍경부터 다시 보기" 버튼, 간단한 footer가 나타난다.
5. **Given** 방문자가 마지막 CTA에서 "처음 풍경부터 다시 보기" 버튼을 누른다, **When** 클릭이 발생한다, **Then** 페이지가 Hero 섹션 최상단으로 이동한다.

### User Story 2 - 모바일에서 읽기 쉬운 세로 흐름으로 같은 콘텐츠를 본다 (Priority: P2)

모바일 방문자가 동일한 6개 섹션(Hero, 4개 장소, CTA/footer)을 단순한 세로 스크롤과 전환으로 접하며, 데스크톱의 확대·교차 인터랙션이 아니라 읽기 중심의 흐름으로 모든 콘텐츠에 접근한다.

**Why this priority**: 모바일 트래픽은 문화관광 콘텐츠에서 비중이 크며, 본문이 숨겨지거나 축약되면 핵심 목적(글 읽기와 사진 감상의 균형)이 깨진다. 다만 데스크톱의 정교한 인터랙션 자체보다는 콘텐츠 완전성이 우선이므로 P1보다 한 단계 낮다.

**Independent Test**: 모바일 뷰포트에서 페이지를 처음부터 끝까지 스크롤하며 모든 장소의 이름, 한 줄 제목, 본문 2문단 전체, 키워드가 축약이나 숨김 없이 노출되는지 확인하는 것으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 모바일 화면 크기로 접속했다, **When** 어떤 장소 섹션에 도달한다, **Then** 데스크톱과 동일한 본문 2문단 전체와 키워드가 모두 표시되며 한두 줄로 잘리거나 감춰지지 않는다.
2. **Given** 방문자가 모바일에서 스크롤한다, **When** 섹션 사이를 이동한다, **Then** 급격한 pin/snap 없이 일반적인 세로 스크롤 흐름으로 전환된다.

### User Story 3 - 키보드 사용자와 모션 축소 설정 사용자가 콘텐츠에 접근한다 (Priority: P3)

키보드만 사용하는 방문자, 또는 `prefers-reduced-motion`을 설정한 방문자가 애니메이션에 의존하지 않고 모든 텍스트와 이미지, CTA 버튼에 접근하고 조작할 수 있다.

**Why this priority**: 접근성은 필수 요건이지만, 핵심 편집형 스크롤 경험(P1)과 모바일 폴백(P2)이 이미 콘텐츠 자체를 완전히 노출하므로, 이 스토리는 그 위에 조작성과 모션 배려를 더하는 계층이다.

**Independent Test**: 마우스 없이 Tab/Shift+Tab과 방향키만으로 CTA 버튼까지 도달해 활성화할 수 있는지, 그리고 시스템 모션 축소 설정을 켠 상태에서 페이지 전체 콘텐츠가 애니메이션 없이도 읽힌다는 것을 확인하는 것으로 독립 검증된다.

**Acceptance Scenarios**:

1. **Given** 방문자가 `prefers-reduced-motion`을 활성화했다, **When** 페이지를 스크롤한다, **Then** 확대·교차·시차 애니메이션이 최소화되거나 제거되고 모든 콘텐츠가 즉시 읽을 수 있는 상태로 나타난다.
2. **Given** 방문자가 키보드만 사용한다, **When** Tab 키로 페이지를 탐색한다, **Then** "처음 풍경부터 다시 보기" 버튼 등 모든 상호작용 요소에 순서대로 도달할 수 있고 포커스 표시가 시각적으로 보인다.

---

### Edge Cases

- 스크롤 진행 중간에 사용자가 스크롤 방향을 위아래로 빠르게 반복해서 바꾸면 어떻게 되는가? → 전환은 스크롤 위치에 연속적으로 반응해야 하며, 특정 지점에서 멈추거나 강제로 이전/다음 섹션으로 튕기지 않아야 한다.
- 이미지 다운로드에 실패하거나 라이선스 조건을 충족하는 사진을 찾지 못한 장소가 있으면 어떻게 되는가? → 해당 장소를 placeholder나 임의의 색상 박스로 채워 완료 처리하지 않고, 어떤 장소의 사진이 준비되지 않았는지 명확히 알린다.
- 매우 좁은 화면(초소형 모바일)이나 매우 넓은 초고해상도 데스크톱 화면에서는 어떻게 되는가? → 본문 폭과 이미지 비율이 화면에 맞게 조정되되, 데스크톱 기준 본문 폭 약 36~48rem 범위와 읽기 행간은 유지된다.
- 이미지 로딩이 늦게 완료되는 저속 네트워크 환경에서는 어떻게 되는가? → 이미지가 로드되기 전에도 장소 이름, 한 줄 제목, 본문 텍스트는 읽을 수 있어야 하며 레이아웃이 크게 흔들리지 않아야 한다.
- 네 장소 섹션의 시각적 배치(이미지·본문 좌우 위치, 여백, 정렬)가 전부 동일하게 반복되면 어떻게 되는가? → 이는 금지된 상태이며, 각 장소는 서로 다른 배치 리듬을 가져야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 페이지를 Hero → 설악산 → 제주 → 순천만 → 보성 녹차밭 → 마지막 CTA/footer의 6개 섹션이 하나의 세로 스크롤 흐름 안에 순서대로 존재하는 단일 페이지로 제공해야 한다.
- **FR-002**: Hero 섹션은 제목("한국의 결"), 영문 표기("LANDSCAPES OF KOREA"), 그리고 페이지의 관점을 설명하는 리드문 전체 문장을 표시해야 하며 제목만 단독으로 두지 않아야 한다.
- **FR-003**: 각 장소 섹션(설악산, 제주, 순천만, 보성 녹차밭)은 다음을 모두 포함해야 한다 — 장소의 한국어 이름과 영문 이름, 풍경의 성격을 짚는 한 줄 제목, 서로 다른 길이의 본문 2개 문단(지정된 실제 문구 전체), 2~3개의 짧은 풍경 키워드, 전체 화면에 가까운 대표 사진 1장.
- **FR-004**: 시스템은 명세에 지정된 Hero 리드문, 네 장소의 한 줄 제목·본문 2문단·키워드, 마지막 CTA의 제목·문장·버튼 문구를 축약하거나 한 문장 캡션으로 줄이지 않고 그대로 콘텐츠로 사용해야 한다.
- **FR-005**: 각 장소의 본문은 사진 위에 얹는 작은 캡션 형태로 표시되지 않아야 하며, 읽기 좋은 크기와 행간을 가진 별도의 읽기 영역(이미지와 나란히 배치되거나 반투명 읽기 패널)으로 표시되어야 한다.
- **FR-006**: 데스크톱 화면에서 각 장소의 본문 영역은 폭이 약 36~48rem 범위 내로 제한되어야 한다.
- **FR-007**: 네 장소 섹션은 이미지와 본문의 좌우 위치, 여백, 정렬이 서로 달라 여행 잡지처럼 시각적 리듬을 만들어야 하며, 모든 장소에 동일한 배치를 반복하지 않아야 한다.
- **FR-008**: 데스크톱에서 섹션 간 전환은 다음 이미지가 서서히 확대되며 들어오고 이전 이미지와 짧게 겹친 뒤 교차하며, 장소 이름·한 줄 제목·본문이 서로 다른 시차를 두고 등장하는 연속적인 스크롤 흐름으로 구현되어야 한다.
- **FR-009**: 시스템은 각 장소 섹션이 나타난 뒤 다음 섹션으로 넘어가기 전까지 본문을 읽을 수 있는 충분한 스크롤 구간을 유지해야 하며, 본문이 등장 직후 곧바로 사라지지 않아야 한다.
- **FR-010**: 스크롤 전환은 섹션별 개별 스크롤 고정(pin)으로 반복적으로 멈추고 풀리는 방식, CSS scroll-snap, 휠 이벤트 가로채기나 강제 스크롤 이동, 또는 한 번의 휠 동작으로 장면 전체가 교체되는 방식을 사용하지 않아야 한다.
- **FR-011**: 모바일 화면에서는 데스크톱의 확대·교차 인터랙션 대신 읽기 쉬운 일반 세로 스크롤 흐름과 단순한 전환으로 대체되어야 하며, 이때도 모든 본문 내용은 데스크톱과 동일하게 전체 노출되어야 한다(한두 줄로 줄이거나 숨기지 않음).
- **FR-012**: 시스템은 `prefers-reduced-motion`이 감지되면 확대·교차·시차 애니메이션을 최소화하거나 제거하고, 모든 콘텐츠가 애니메이션 없이도 완전히 읽고 볼 수 있는 상태를 유지해야 한다.
- **FR-013**: 모든 인터랙티브 요소(예: 마지막 CTA의 "처음 풍경부터 다시 보기" 버튼)는 semantic HTML 요소로 구현되고 키보드만으로 접근·조작 가능해야 하며 시각적으로 식별 가능한 포커스 상태를 가져야 한다.
- **FR-014**: 마지막 섹션은 지정된 CTA 제목("오래 보고 싶은 풍경은 천천히 남습니다"), 문장, 그리고 "처음 풍경부터 다시 보기" 버튼과 간단한 footer를 포함해야 하며, 버튼 활성화 시 페이지 최상단(Hero)으로 이동해야 한다.
- **FR-015**: 시스템은 Hero용 한국 자연 풍경 사진 1장과 설악산·제주·순천만·보성 녹차밭 각 1장 이상의 실제 대표 사진을 재사용 조건이 확인 가능한 출처에서 확보하여 사용해야 하며, placeholder 이미지, 임의의 단색 박스, 외부 URL로의 이미지 hotlink를 최종 결과에 남기지 않아야 한다.
- **FR-016**: 사용된 모든 이미지는 각각 풍경을 구체적으로 설명하는 한국어 대체 텍스트(alt)를 가져야 한다.
- **FR-017**: 어떤 장소의 실제 대표 사진을 확보하지 못한 경우, 시스템은 해당 장소를 placeholder로 채워 완료 처리하지 않고 어떤 장소의 사진이 누락되었는지 명확히 알려야 한다.
- **FR-018**: 모든 페이지 내부 경로와 이미지 경로는 상대 경로여야 하며, GitHub Project Pages의 하위 경로에서 서빙되어도 정상 동작해야 한다.
- **FR-019**: 최종적으로 사용되는 각 대표 사진 파일의 용량은 원본의 라이선스와 화질을 훼손하지 않는 범위 내에서 약 300~500KB를 넘지 않도록 최적화되어야 한다.

### Key Entities

- **장소 섹션(Place Section)**: 설악산, 제주, 순천만, 보성 녹차밭 각각을 나타낸다. 속성: 한국어 이름, 영문 이름, 한 줄 제목, 본문 문단 1, 본문 문단 2, 키워드 목록(2~3개), 대표 사진(및 그 alt 텍스트), 화면 내 배치 스타일(이미지·본문 좌우 위치와 정렬).
- **Hero 섹션**: 페이지 진입점을 나타낸다. 속성: 제목("한국의 결"), 영문 표기("LANDSCAPES OF KOREA"), 리드문, 대표 사진.
- **마지막 CTA/Footer 섹션**: 여정의 마무리를 나타낸다. 속성: CTA 제목, CTA 문장, 버튼 레이블 및 동작(Hero로 이동), footer 콘텐츠.
- **이미지 자산(Image Asset)**: 각 섹션에서 사용되는 다운로드된 사진 파일을 나타낸다. 속성: 파일 경로, 출처/촬영자, 원본 URL, 라이선스, 확인 날짜, alt 텍스트 — 이 속성들은 CREDITS.md에도 대응 기록된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자가 Hero부터 마지막 CTA까지 페이지 최상단에서 최하단까지 스크롤하는 동안, 모든 6개 섹션(Hero, 4개 장소, CTA/footer)의 텍스트와 이미지가 예외 없이 완전한 형태로 노출된다.
- **SC-002**: 데스크톱과 모바일 양쪽에서, 각 장소의 본문 2문단 전체 글자 수가 축약 없이 100% 그대로 표시된다.
- **SC-003**: 네 장소 섹션 중 동일한 이미지·본문 좌우 배치 패턴을 사용하는 섹션이 2개를 초과하지 않는다(즉, 최소 절반 이상의 장소가 서로 다른 배치를 사용한다).
- **SC-004**: `prefers-reduced-motion`을 설정한 방문자가 애니메이션이 재생되지 않는 상태에서도 모든 장소의 이름, 한 줄 제목, 본문, 키워드, 이미지를 스크롤만으로 100% 확인할 수 있다.
- **SC-005**: 키보드만 사용하는 방문자가 마우스 없이 Tab 키 조작만으로 페이지의 모든 인터랙티브 요소(최소한 마지막 CTA 버튼)에 도달하고 활성화할 수 있다.
- **SC-006**: 최종 페이지에 사용된 이미지 5장(Hero 1장 + 장소별 1장 이상 총 4장 이상) 전부가 실제 촬영된 사진이며, 각 이미지에 대응하는 출처·라이선스 기록이 CREDITS.md에 100% 존재한다.
- **SC-007**: 페이지를 GitHub Project Pages의 하위 경로(예: `/repo-name/`)에서 열었을 때 모든 이미지와 내부 링크가 깨지지 않고 정상적으로 로드된다.
- **SC-008**: 페이지에서 사용되는 대표 사진 5장 각각의 최종 파일 용량이 300~500KB를 넘지 않는다.

## Assumptions

- 페이지는 한국어를 주 언어로 하며, 영문 표기(장소명, Hero 부제)는 명세에 주어진 대로 병기 형태로만 사용하고 전체 다국어 전환 기능은 이번 범위에 포함하지 않는다.
- "충분한 스크롤 구간"의 정확한 픽셀/시간 값은 명세에 수치로 주어지지 않았으므로, 평균적인 읽기 속도로 본문 2문단을 읽는 데 필요한 시간(대략 8~12초 상당의 스크롤 구간)을 유지하는 것을 합리적 기준으로 가정한다.
- 실제 사진은 구현 단계에서 Wikimedia Commons, Unsplash, Pexels 등 재사용 조건을 확인할 수 있는 출처에서 직접 검색·다운로드하며, 이 스펙 작성 시점에는 아직 확보되지 않았다.
- 사이트는 별도의 백엔드, 로그인, 데이터베이스 없이 정적 파일만으로 GitHub Pages에 배포 가능한 구조를 가정한다.
- 브라우저 지원 범위는 최신 데스크톱/모바일 브라우저(Chrome, Safari, Edge, Firefox의 최근 버전)를 가정하며, 구형 브라우저에 대한 별도 폴백은 범위에 포함하지 않는다.
